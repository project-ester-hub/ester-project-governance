# ESTER zotero setup

_draft date: 2026-11-03_

The ESTER Project Team has an own group library on zotero: https://www.zotero.org/groups/6232672/ester-project.

We recommend using the Better BibTex plugin for citation management. The manual can be found here: https://retorque.re/zotero-better-bibtex/installation/index.html .

## Folder structure

In the library, folders can be created thematically (e.g. "datasets") as well as per paper (e.g. "bias_paper"). Each publication should have their own folder. To avoid confusion, folder naming should be unambigious and not contain too many abbreviations. After successfull publication, the publication year may be added to the folder name, making it easier to find and also indicating the finalisation.

## Tagging

If a new paper is added, tags providing information on area (either country or region) and topic are appreciated. There is the option of automatic tagging available in the settings: Tags are then extracted from the paper title. Whether this is enough for finability is up to the team members. It's recommended to tag rather more than less.

## Settings for clean synchronisation

For syncing, a few shared settings will be helpful to the team:

### citation key management

Make sure to keep keys unique within each library, which is the standard Better BibTex setting. This will keep a citation key for an entry unique to each folder in our group. As folders are the basis for an export for a publication, this ensures citation keys in a publication script don't get obsolete when something is changed in the group library in general.

Also, please keep "Ignore upper/lowercase when comparing for uniqueness" to the default "yes", this will help a typo doesn't mix up citations by accident.

Citation keys can be auto generated by Better BibTex following a "function" that is easily customisable. Sophie uses "auth.lower + "_" + year", which creates citations like "smith_2022". If a new paper is added and the needed citation key is already present, a letter is added as postfix by Better BibTex, creating a "smith_2022a" for the second paper with this author-year-combination.

In the Better BibTex settings, just below the citation key formula you can set a slider when the citation key will be pinned (German: "Zitierschlüssel automatisch ausfüllen nach x Sekunden"). If this is set to 0, the citation keys are being generated new every time the library is exported. Therefore any value larger than 0 shoud be chosen.

I also recommend checking "regenerate citation key after changes", so corrections to the authorname or year also continue on to the citation key. This does not change postfixes, as they are dependent on the internal zotero ID, which does not get changed with a revision of attributes. Of course a modification in e.g. authorname or year then changes the whole citation key. This needs to be communicated to the team when others are working with this entry!

Setting up auto-generation does not change old keys, entries need to be regenerated manually: Mark an entry, right-click --> Better BibTex --> Regenerate Better BibTex key. Remember, key changes are only done folder-wise.

By using the auto-generated citation keys, you cannot change keys by hand (even if you change the text in the citation key area, it will not be saved).

### PDFs and other attachments

Do not sync PDFs or other attachments, we will run out of storage fast. Instead, make sure you know where your PDFs are stored so you can bring them along whenever you need to change hardware.
